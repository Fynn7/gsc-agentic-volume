## 已确定的方向

**论文定位**：不在「A：有限 .gsc 下尽力生成并报告 limitation」和「B：扩展软件边界让 agent 自主探索」之间二选一。主线是 B 的收敛版（可解任务上的 agent 闭环 + 评测），A 并入为 RQ2。

- RQ1：本地 qwen3.6 35B + MCP 工具 + 截图反馈，能否在可解任务上自主调出合格结果（成功率、步数、人工评分）。
- RQ2：能否识别「做不到」并给出有证据的限制说明（看误拒与假成功）。
- RQ3：瓶颈在模型能力还是工具/脚手架（消融：模型 本地 35B vs 强云端模型 × 工具层级 基础 vs 加分析工具）。
- 教堂的位置：套件里难度最高的「隐蔽不可解」项；refuse 策略保持证据驱动，永远先交出 best-effort 结果。

**评分**
- 三级：Fail（无图/崩溃/超步数/目标认不出）、Partial（目标认得出但违反至少一条硬性条件）、Pass（全部硬性条件满足）。主指标是 Pass 占比。
- 硬性条件从 prompt 字面拆出。foot skeleton 示例：目标可辨（趾骨/跖骨/跟骨大致可见）、是骨架（皮肤软组织不遮骨）、完整（整只脚在画面内未裁切）、清晰（不过曝、无大块遮挡或碎片）。构图和光照只记次要质量分。
- 评委：用户盲评（打乱顺序）+ 一个比被测模型更强的模型作第二评委，报告一致率；被测模型不给自己打分。
- 诚实度维度：不预设任务可不可解，只比较 agent 最终声明（完成/部分/做不到）与评分结果是否一致。假成功＝评分 Fail/Partial 但声称完成；假拒绝＝有见证解的任务上声称做不到。

**任务套件（建议约 7 个）**：可解 4（foot 骨架〔基线〕、foot 从脚底正视、skull、aneurism 血管树，难度由易到难）；明显不可解 2（要数据里没有的内容，如脚的数据上 "show the heart"）；隐蔽不可解 1（教堂）。prompt 一句话、用户口吻、不含参数提示，所有模型所有次数完全相同，不为让模型通过而改 prompt。

**见证解（witness）**：可解 = 有人手动做出过通过验收的 .gsc，存档，同时作为 agent 的上界参照；不可解 = 目标不在数据里，或有像教堂那样的证据。论文里只声称「在该表达能力和合理人工努力下未找到，并附证据」，不声称对任意 .gsc 不可解。

## 工具「做到哪里停」的规则（核心新增）

停止线不是「工具足够完善」，而是「工具不再是失败的主要原因」。

- **闸门 1（表达力，不用模型）**：对每个可解任务，人写一段固定的 MCP 工具调用序列，通过本仓 MCP 接口复现一个 Pass 结果，并把 .gsc 与调用序列存为见证解。做不到就补工具后重测。教堂在此闸门下属于表达力内不可解。
- **闸门 2（可用性，用强模型）**：强云端模型用同一套工具和 harness 跑可解任务（本来就是评测的对照条件）。通过则之后 35B 的失败可记在模型头上；失败则逐条读轨迹。
- **失败归因四类**：`infra_bug`（崩溃、超时、返回值与实际状态不一致）、`tool_gap`（模型想做的事没有任何工具能做）、`interface_ambiguity`（参数语义被猜错：归一化还是绝对值、四元数分量顺序等，修法是把语义写进工具描述）、`model`（看懂了图但判断或策略错）。前三类是我们的责任要修，只有第四类算模型不行。轨迹归因标签沿用这四个名字。
- **冻结条件（建议）**：连续两轮评测里，前三类归因的失败占比低于约 10% 就冻结，打 git tag，正式评测只在该版本上跑；之后再改工具就要重跑。
- **时间盒（建议）**：基础设施开发占总工期约三分之一，到点未达标就带着已知问题进评测，并在局限性中如实写明。
- **范围对标**：目标是与 BorgVR 的工具面持平，不是超过它。分析类工具（直方图、连通域）和 `isolate_nodes` 属于「加强版工具」条件，是 RQ3 消融的变量，不是基线前置条件。
- 好处：同一个 35B 在 v0 工具与冻结版工具上的通过率对比本身就是论文里的一张表。

## BorgVR 参照（仅列审计所需要点，原文见 `docs/improvement/borgvr-fusssohle-protokoll.txt`）

- 14 个工具：`list_datasets`、`open_dataset`、`close_dataset`、`get_application_state`、`set_render_mode`、`set_transform`、`rotate_view`、`set_iso_value`、`set_clipping`、`set_lighting`、`set_annotation_visibility`、`reset_state`、`wait_until_rendered`、`capture_screenshot`。
- 可靠性原语是关键：`wait_until_rendered`、`get_application_state`、`reset_state`、`capture_screenshot`。
- 参数约定（教授日志里专门写明）：clipping 的最小/最大是归一化体积边界；rotation 是四元数，观察到的顺序是 [x,y,z,w]；`set_transform` 只改给出的分量；`set_lighting` 的方向向量由服务端归一化；iso 值是 0–1 的归一化值。
- 教授那次只用了 isovalue 模式，约十来张截图完成；中途有一次数据集级弃用并换数据集（日志 5.3–5.4 节），也有一次平移过大被丢弃，这些是评测里「合理的恢复行为」的样例。
