# 02 数据集事实：Christmas Present

> 来源：TU Wien 数据集页、TU Wien 2006 圣诞卡、仓库代码，以及 run a 保存的 8 张切片。标签含义见 `00-README.md`。

## 1. 数据集来源与版本

- 【实测】数据集页描述它是一份圣诞礼物的工业 CT 扫描，提供三档分辨率：246×246×221、328×328×294、492×492×442。当前项目使用最小的 246×246×221 一档。页面地址：<https://www.cg.tuwien.ac.at/research/publications/2006/dataset-present/>
- 【实测】仓库的 `scripts/volume_context/readers/tuwien.py` 把它当作 TU Wien 二进制 DAT：6 字节头（三个小端 uint16 维度）加 uint16 体素，不含间距、原点和朝向信息。
- 【实测】`src/volume.py` 的 `prepare()` 会把体素按**全体积 min/max 线性映射到 uint8**，写成 `render.raw`。传输函数的横轴就是这个 uint8 除以 255。所以文档里所有“密度”都是 renderer-uint8 域的数值，**它受全体积最大值（金属件）拉伸，不是物理密度**。
- 【提案】更高分辨率的 328 或 492 档可以在方法稳定后用来做泛化检验。

## 2. 内容物

### 2.1 官方信息

TU Wien 2006 年的圣诞卡写明：这份礼物里有一个雪景球，球里是圣斯蒂芬大教堂（Stephansdom）的模型，礼物里还有一些隐藏的小生物。卡片地址：<https://www.cg.tuwien.ac.at/research/publications/2006/xmas-2006/xmas-2006-card.pdf>（原文细节我没有逐字复核，请以原卡片为准）。

由此得到任务术语和数据的对应：

| 任务里的词 | 数据里对应的物体（部分为推断） |
|---|---|
| the box | 外层的礼盒，薄壁，密度约 0.16–0.24 |
| the ball-like present | 雪景球的玻璃壳，薄壳，密度约 0.6–0.78，形状像灯泡，颈部朝向大 z |
| the chapel | 球内的大教堂模型。我把约 0.28 的块状物当作它【推断】 |

### 2.2 从切片里看到的结构【实测】

沿 x 方向的切片（x=120、122、123）显示，从外到内是：

1. 外层礼盒的薄壁和顶部有一些零散的亮点（包装噪声）。
2. 一个灯泡形的薄玻璃壳，球体在小 z 一侧，颈部在大 z 一侧向下收窄。
3. 球颈内有一圈薄壁的矩形支架，支架里装着两样东西：
   - 上方：一个**块状物**，顶部有锯齿状的垛口，右侧有一根竖直的细柱。密度约 0.28。
   - 下方：一个**亮色小造型**，轮廓像一个弯曲的小人形或动物，密度约 0.5。
4. 沿 z 方向的切片（z=100–110）显示，球壳的横截面是一个圆，圆心约在 (x, y) = (124, 121)，半径约 43 体素；圆心有一个很小的方块（约 4 体素）。礼盒本身相对球倾斜了一个角度。
5. 体积外围散布着 **12 个高密度小件**，纺锤形（两头宽中间窄），沿 z 轴俯视时只能看到其中约 5 个，侧视时呈 3 排 4 列的点阵。我推断它们是金属紧固件，这是**推断**，没有核对过。

### 2.3 实测数值

数据来自 8 张切片，数值域 renderer-uint8，除以 255 归一化。

| 结构 | 归一化密度 | 在 x 切片里的位置（行 = z，列 = y） |
|---|---|---|
| 礼盒壁 | 0.16–0.24 | 外框 |
| 块状物（候选教堂） | ≈0.28，p10–p90 为 0.25–0.30 | y 约 108–145，z 约 119–149 |
| 亮色小造型 | 0.49–0.53 | y 约 120–140，z 约 155–191 |
| 玻璃球壳 | 0.60–0.78，1 到 2 体素厚 | 灯泡轮廓 |
| 12 个小件 | 大于 0.9 | 体积外围 |

块状物和小造型的 y、z 范围是我对三张 x 切片做连通域测量得到的，三张切片之间一致；**x 方向的范围无法从现有切片得到**，只知道 x=120、122、123 都穿过它。如果它关于球的轴线大致对称，x 范围以 124 为中心取 ±25 左右是合理的初值，但这只是猜测。

## 3. 坐标约定【实测，来自 `src/volume.py` 与 `src/renderer.py`】

| 项目 | 约定 |
|---|---|
| 存储轴顺序 | x 变化最快；NumPy 形状为 `(z, y, x)` |
| 切片图像的行列 | `axis=x` 时行是 z、列是 y；`axis=y` 时行是 z、列是 x；`axis=z` 时行是 y、列是 x；`verticalFlip` 为 false，第 0 行对应索引 0 |
| crop | `[x0, x1, y0, y1, z0, z1]`，存储体素坐标，**半开区间**，不是归一化坐标 |
| 相机 | 正交；欧拉角按 X、Y、Z 的顺序施加；默认视线沿 z 轴 |
| 朝向 | `orientation` 为 `unknown`，不能假设解剖或物体的“上下” |
| 观察到的几何朝向 | 灯泡的球体在小 z 一侧，颈部在大 z 一侧；沿默认视线看，球壳表现为同心环 |
| 传输函数域 | renderer-uint8 除以 255，范围 [0, 1] |

## 6. 真值标注协议（人工，一次性）

评测需要一份“什么算教堂”的真值（见 `06-evaluation-protocol.md`）。因为节点编号在不同参数下可能变化，真值用**节点签名**表示，而不是节点编号。

### 6.1 步骤

1. 完成 `07-worker-implementation-plan.md` 的阶段 1 与阶段 2 后，运行 `analyze_structure`，得到节点表。
2. 运行 `render_candidates`，得到候选缩略图联系表。
3. 标注者在联系表上指出哪些节点是“教堂”（可以是一个，也可以是教堂加一个附属构件），哪些必须排除（球壳、礼盒、金属件，以及你认为不属于教堂的节点）。
4. 把对应节点的签名（平均密度、包围盒、体素数）写进 `eval/golden/christmas-present.json`。
5. 用旧的两次运行（run a、run b）的最终帧跑一遍评分，**预期两者都判失败**，作为评分器自身的健全性检查。

### 6.2 JSON 模板

下面是模板，尖括号里的值必须由标注者填写，我没有填写任何 x 方向的数值。

```json
{
  "version": 1,
  "dataset": "tuwien-christmas-present-246x246x221",
  "volumeHash": "<volume.json 里的 volumeHash>",
  "targets": [
    {
      "annotatorNote": "候选教堂块状物，仅供人看，不会给 agent",
      "meanIntensity": 0.28,
      "meanTolerance": 0.04,
      "bbox": ["<x0>", "<x1>", 106, 147, 117, 150],
      "bboxIouMin": 0.5,
      "minVoxels": 300
    }
  ],
  "mustExclude": [
    {"annotatorNote": "玻璃球壳", "meanIntensity": 0.69, "meanTolerance": 0.12, "kind": "shell"},
    {"annotatorNote": "礼盒壁", "meanIntensity": 0.20, "meanTolerance": 0.06, "kind": "any"},
    {"annotatorNote": "金属小件", "meanIntensity": 0.92, "meanTolerance": 0.08, "kind": "any"}
  ],
  "thresholds": {"coverageMin": 0.8, "leakMax": 0.05}
}
```

y、z 的范围取自第 2.3 节的实测，并向外留了几个体素的余量；平均密度和容差来自同一节的实测。**真值文件不得放进 agent 能访问到的任何目录**（见 `07` 的护栏）。

## 7. 全量体素实测补强（2026-10-26，替代 8 切片推断）【实测】

方法：后端 `/api/volume/import` 导入 `volumes/present246x246x221.dat`，取 uint8 `render.raw`（z,y,x，x 最快），256-bin 直方图 + 26-连通域标注。总量 13,379,292 体素。

直方图（归一化密度）:

| 区间 | 体素数 | 占比 | 备注 |
|---|---|---|---|
| 0.00–0.05 | 12,129,302 | 90.69% | 背景 |
| 0.20–0.24 | 147,445 | 1.10% | 含礼盒壁（与 §6 真值 0.20±0.06 一致） |
| 0.24–0.32 | 68,613 | 0.51% | 教堂候选带：碎成 **4837 个连通域** |
| 0.26–0.30 | 30,246 | 0.23% | 窄带：3641 个连通域 |
| 0.30–0.36 | ～8,000 | 0.06% | 基本无成块结构 |
| 0.50–1.00 | 35,959 | 0.27% | 致密体 |
| ≥0.60 | 22,531 | 0.17% | 壳层，包围盒 z23–206/y32–208/x33–212 |

连通域扫描（26-连通，取最大若干块）：

| 带宽 | 最大块 | 占带比 | 最大块中心偏离体积中心 | 结论 |
|---|---|---|---|---|
| 0.22–0.26 | 67,104 体素 | 72% | 19 体素 | 唯一接近“中央整块”的候选 |
| 0.24–0.32 | 13,511 体素 | 20% | 62 体素 | 碎成 6 块 6K~13K + 数千碎片 |
| 0.26–0.30 | 9,171 体素 | 30% | 62 体素 | 仍是两大块 + 碎片 |
| 0.28–0.34 | 5,024 体素 | 28% | 23 体素 | 最大块仅 5K，盒 z102–144 |
| 0.20–0.40 | 155,679 体素 | 69% | 10 体素 | 全连通成一块（墙+教堂+壳膜经 PVE 桥接） |

复核结论（对照 §6 真值假设）：

- **0.28±0.04 偏高**：最连贯的中央团在 **0.22~0.26**（6.7 万体素、偏离中心仅 19 体素、包围盒 z68–190/y56–196/x54–187）。0.28 以上基本只剩碎片，真值模板的教堂均值建议复核为 0.24±0.04。
- **教堂不可纯 `.gsc` 分离的直接证据**：任一带宽下都不存在“一个中央整块 + 其余全碎”的分布；0.2~0.4 宽带下全部连成一块说明各部分经 PVE 桥接拓扑相连任何单阈值都不能在不断开教堂本体的前提下甩掉壳膜。
- 壳层包围盒（z23–206/y32–208/x33–212）与中央团包围盒相交：任一覆盖教堂 ≥80% 的 AABB 必穿壳，几何上不可分（与 09 的 AABB 论证一致）。
