# 05 改进路径与路线图

> 所有成本是**粗估的人工工时**，仅用于排序，不是承诺；所有“预期效果”是推断，在对应实验（见第 5 节）做完之前不要当成结论。证据标签见 `00-README.md`。

## 1. 设计原则

1. **程序负责几何与搜索，模型负责语义选择**。把开放的连续搜索改成对少量带编号候选的选择题。
2. **每个改动都要能单独做 A/B**。新工具放在 `toolProfile: v2` 后面，旧 profile 行为不变。
3. **先有可验证的评分，再做自动搜索或训练**。没有评分器的优化，只是更快地走错方向。
4. **“不给模型语义标签”的原则保留**。节点只带数值，“哪个是教堂”由模型看图选，真值由人工一次性标注。

## 3. 各路径详述

### 路径 A：暴露能力（止血）

- **机制**：
  1. `render_scene` 新增 `tfType`（`smoothstep` 或 `gaussian`）和 `lighting`（映射到渲染模式 7）。高斯窗里 `tfStart` 是中心，`tfWidth` 是标准差，和原生 `settfparams true` 的语义一致。
  2. `inspect_scene` 额外返回 64 档直方图和峰值带（数值，不含语义）。
  3. 新增 `probe_voxel(x,y,z)`：返回该位置及 3×3×3 邻域的 renderer-uint8 归一化值。它补上“切片里看到灰块却不知道多灰”的缺口。
  4. 现有的 `render_scene` 返回里其实已经包含完整的 `scene`，但模型没有读到；增加醒目的 `changedFields`（本次改了什么）和 `warnings`（例如 crop 不是全体积），解决“省略即保持”造成的黏性参数混淆。
  5. 采样与记忆：提高 `contextSize`，**并确认 Ollama 实际生效的上下文长度与之一致**（当前代理不设置 `num_ctx`，需用 `ollama ps` 核对，或通过服务端环境变量、派生 Modelfile 设置）；关闭或放宽 Codex 自动压缩，保持 `think=true`，temperature 调到 0.6 左右；节点表等关键事实由服务端回传，不靠模型摘要。
- **成功标志**：在不引入结构工具的情况下，E2（见第 5 节）的成功率明显高于 E0。
- **退出条件**：如果 E2 已经稳定成功，路径 B、C 可以降优先级，但 `verify_frame` 仍应保留，因为它是评测基础。

### 路径 B：结构树加选择题（核心）

- **机制**：`analyze_structure` 在服务端用纯 numpy 算（仓库的依赖策略只假定 numpy 与 Pillow，`Start-VolumeTUI.ps1` 只校验这两个包；scipy 最多作为可选加速，不能成为硬依赖）：梯度门控直方图 → 材料带 → 每个带做三维连通域 → 属性（体素数、包围盒、重心、平均密度、最大距离值以区分薄壳）→ 包含关系树 → 把形态相近的小件归成“家族”（例如 12 个金属件算一个节点）。`render_candidates` 对每个节点单独渲染 4 个视角，拼成一张带数值标签的联系表。模型只回答“哪个节点像小教堂模型”。
- **为什么有效**【推断】：它把 R2、R5、R6、R7 同时降级。候选只有 4 到 8 个，且每个都是从零开始的干净渲染，不再有球壳和金属件的混淆；节点表是确定性的，不依赖模型记忆。
- **成功标志**：在真实体数据上，节点表里有一个节点的平均密度约 0.25 到 0.31，且包围盒落在 02 第 2.3 节的 y、z 范围附近；同时有一个“家族”节点包含约 12 个大于 0.85 的小件，有一个薄壳节点包住前两者。
- **风险与后备**：
  - 薄壳和礼盒壁是 1 到 2 体素厚，容易在去噪或阈值时碎裂。后备是对高密度带做更保守的形态学闭运算，或改用路径 D 的分割结果。
  - 块状物与支架薄壁相连，连通域可能把它们合在一起。后备是按距离值做腐蚀后再标记，再把标记扩回。
  - 建议先在合成体（阶段 1 生成）上调通，再上真实数据。

### 路径 C：体素手术加验证（核心）

- **机制**：
  1. `isolate_nodes(keep=[...])`：把所有未选节点的体素置零（可对保留节点做 1 到 3 体素的膨胀，避免丢掉部分体素效应的边缘），写成新的派生体数据（新的 `render.raw` 和 `render.dat`），再自动用光照加低阈值渲染一帧。
  2. `verify_frame(frame, targetNodes)`：对同一相机再渲染一次“只含目标节点”的参考图，计算覆盖率（参考里的像素有多少出现在候选帧里）和泄漏率（候选帧里有多少像素不能被参考解释）。
  3. `finish_task` 自动附带上述指标。
- **要点**：派生体数据必须和现有的“场景绑定体数据哈希、渲染载荷哈希”机制兼容，因此作为带 `parentVolumeHash` 的第一等体数据登记，而不是绕过校验。
- **成功标志**：用旧的 run a、run b 最终帧去验证，应判失败；用正确节点渲染的帧，应判通过。
- **局限**：验证证明不了“节点就是教堂”，只证明“画面里只有被选中的节点”。

### 路径 D：切片当视频（备选）

- **机制**：在一张 x 切片上给 SAM 2 一个点或框，向相邻切片传播得到 3D 掩膜；或用 SAM 3 的文本提示。掩膜作为一个节点，复用路径 C。
- **前置验证**：SAM 在工业 CT 灰度图上的表现未知；需要 GPU 和模型权重。先用一个脚本在 8 张已有切片上做离线试验，再决定是否集成。
- **何时启用**：当路径 B 的自动分割把块状物和支架合并、或碎成多块、且形态学后备无效时。

### 路径 E：批量联系表加进化搜索

- **机制**：原生渲染器每次启动约 3 秒，大部分是进程和体数据加载。一个 GSC 脚本里可以做多次相机设置和截图，所以一次调用可以出 16 个窗口乘 4 个视角的联系表；让观察预算按“决策次数”而不是“渲染次数”计。评估器用程序化指标加 VLM 两两比较，进化迭代。
- **前置**：评测协议（`06`）和路径 C 的验证器；否则只是在没有梯度的黑盒上随机搜。
- **何时做**：M3 之后，如果结构树方法在别的数据集上泛化不佳，才需要它。

### 路径 F：代码沙盒加小 DSL（探索性）

- **机制**：给模型一个受限的 Python 环境和几个函数，例如 `vol.band(lo,hi)`、`vol.components()`、`show(mask, view)`，让它写分析代码。
- **为什么暂不排期**：现有 harness 刻意关闭了 shell 工具；沙盒要重新做安全设计。路径 B 已经把“代码擅长的部分”放进了服务端，模型只做选择，收益重叠。
- **何时重新考虑**：当任务从“选一个节点”变成需要组合多个节点、做布尔运算或按空间关系筛选时。

### 路径 G：合成课程加强化学习（长期）

- **机制**：用阶段 1 的合成体生成器造成千上万个“盒包球包物体”的嵌套场景，真值掩膜已知；奖励是 `verify_frame` 的覆盖率与泄漏率组合，不需要 VLM 打分；用 GRPO 之类的方法微调工具调用策略。
- **前置**：评测协议、合成体生成器（阶段 1 会产出）、验证器（阶段 2 会产出）、训练基础设施。
- **主要风险**：35B 的稀疏模型做 LoRA 强化学习需要的显存和工程量不小；更现实的做法是在 8B 级别的视觉语言模型上做，再回头评估迁移。收益在拿到 E3 结果之前无法判断，建议先看 E3。

### 路径 H：可微渲染优化传输函数（后备）

- **机制**：用 PyTorch 写一个正交光线投射器（246³ 的体数据在 GPU 上很小），用 CLIP 或 SigLIP 的相似度加稀疏、平滑正则去优化一个 64 节点的 RGBA 传输函数，再用原生渲染器做一致性复核。
- **何时做**：如果结构树方法不可行（例如目标不是一个可分离的连通物体，而是密度带内的纹理），这条路才有意义。

## 4. 路线图

| 里程碑 | 内容 | 出口条件 |
|---|---|---|
| M0 基线与探针 | 阶段 0 的基线测试；Spike S1 到 S8 | 所有 Spike 有结论，失败的有后备 |
| M1 止血版 | 阶段 3 的 v2-lite（路径 A）；阶段 5 的评分器骨架 | 可以跑 E0、E1、E2 |
| M2 结构工具 | 阶段 1 与阶段 2：`analyze_structure`、`render_candidates`、`isolate_nodes`、`verify_frame` | 在真实体数据上节点表满足路径 B 的成功标志 |
| M3 真值与 A/B | 人工标注真值；跑 E0 到 E3；写出结果报告 | E3 相对 E0 的差异有置信区间 |
| M4 扩展 | 视 M3 结果选择 D、E、G、H | 单独立项 |

决策门（阈值是建议值，可按你的容忍度调整）：

1. **M0 之后**：如果 Spike S2 或 S3 失败（光照或高斯窗在你的构建上不可用），路径 A 里对应的部分改为用派生体数据加 smoothstep 实现，不依赖原生新功能。
2. **M2 之后**：如果节点表在真实体数据上不满足成功标志，优先尝试路径 B 的形态学后备；两轮仍不满足，再启用路径 D。
3. **M3 之后**：如果 E2 的成功率已经与 E3 相当，说明“表达力和信息”就是瓶颈，结构工具可以降级为可选；如果 E3 明显高于 E2，保留结构工具并考虑路径 E、G。

## 5. 实验阶梯

每一档都只改一类因素，这样差异能归因。每档跑 10 次、固定相同的任务文本和体数据。

| 编号 | 配置 | 隔离的因素 |
|---|---|---|
| E0 | 当前配置：旧工具、`think=true`（`reasoning_effort=medium`）、temperature 0、`contextSize` 16384 | 基线 |
| E1 | 旧工具；提高上下文、关闭或放宽自动压缩、保持 `think=true`、temperature 0.6 | 记忆与采样（R4、R6） |
| E2 | v2-lite：E1 加高斯窗、光照、直方图、`probe_voxel`、完整状态回报 | 工具表达力与信息（R1、R2、R5） |
| E3 | v2-full：E2 加 `analyze_structure`、`render_candidates`、`isolate_nodes`、`verify_frame` | 结构化方法 |
| E4（可选） | E3 换用 Qwen3.8-27B 稠密模型 | 模型结构 |

记录的指标和统计方法见 `06-evaluation-protocol.md`。注意：每档只有 10 次运行，成功率的置信区间很宽（例如 7/10 的 95% 区间约为 39% 到 90%），所以只有差异很大时才应下结论，其余情况要增加运行次数。

## 6. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 薄壳在去噪或阈值后碎裂，包含关系错误 | 节点树不可用 | 合成体上先调；形态学后备；路径 D |
| 原生渲染器的光照模式 7 在本构建上报错 | 路径 A 的光照部分失效 | Spike S2；用派生体数据加 smoothstep 替代 |
| 单次工具调用超过 Codex 的 MCP 默认超时 | 调用被中止 | 预计算分析；联系表控制节点数；提高工具超时（需核实配置项名称） |
| 派生体数据破坏哈希绑定与证据链 | 现有的证据校验失败 | 作为带 `parentVolumeHash` 的第一等体数据；补测试 |
| 真值标注错误 | 评测结论错误 | 两人独立标注或同一人隔天复核；标注签名而不是编号 |
| 过拟合这一个数据集 | 方法在别处不成立 | 阶段 1 的合成体做泛化检验；之后换 328 或 492 档，或换别的数据集 |
| 10 次运行的统计功效不足 | 误判改进幅度 | 看置信区间；必要时加到 20 次 |

## 7. 什么情况下应该推翻本方案

1. 在完整体数据上，块状物的密度和其他结构大量重叠，无法用任何单一特征把它分离出来。此时路径 B 的前提不成立，转向路径 D 或 H。
2. 人工确认后发现“教堂”并不是单个连通物体，而是由多个分离部件和不同密度带构成。此时选择题的单位要从“节点”改成“节点集合”，`isolate_nodes` 已经支持多节点，但 `verify_frame` 的阈值需要重新标定。
3. E2 已经稳定高成功率，且 E3 没有额外提升。此时应该保持简单，只保留 v2-lite 和验证器。
